# ADR-016: M12 Window 2.0 -- composite-proxy, drag-capture, z-order, preventable close

## Контекст
M7-Window -- статичная композиция (фон + bar + label) без drag/resize/close/z-order.
Master prompt §4.1: составные виджеты (Window, будущий ScrollPanel) требуют
"один публичный handle -> несколько узлов Storage" без изобретения новой системы
хранения. Drag требует курсорного ввода ВНЕ узла-источника (курсор уходит с bar
при перетаскивании) -- текущий Dispatcher (M3) такого механизма не имел.

## Решение

### 1. Composite-proxy (общий механизм, не window-специфичный)
- Внутренние узлы -- ОБЫЧНЫЕ дети в дереве Storage: destroy-каскад M1 сносит их
  сам, hit-test/render их не отличают от пользовательских.
- Proxy держит ссылки на части: `handle._parts = { bar=, title=, close=, grip= }`
  (полноценные proxy) + `handle._win` (состояние окна) + `handle._kernel`.
- Widget-методы -- отдельная metatable ПОВЕРХ базовых методов proxy:
  `__index = WindowMethods[k] or baseMethods[k]`. Базовые методы не
  засоряются; proxy-пул остаётся единым.
- Proxy:acquire ВСЕГДА сбрасывает metatable к базовой (пул мог вернуть
  composite-handle); Proxy:release чистит _parts/_win/_kernel и сбрасывает
  metatable. "Грязных" handle в пуле не бывает.
- WindowMethods:destroy переопределён: отпускает части в пул ДО базового
  destroy (каскад убивает узлы частей).

### 2. Drag-capture в Dispatcher (не новый event-bus)
- `Dispatcher:beginDrag(fnMove, fnEnd)` -- захват курсора: fnMove на каждый
  onCursorMove, fnEnd на первый mouseup ГДЕ УГОДНО. Повторный beginDrag
  заменяет предыдущий. `endDrag()` -- принудительное завершение.
- Пока drag активен, hover (mouseenter/mouseleave) ПОДАВЛЕН -- под курсором
  "виртуально" висит захвативший узел. После mouseup hoveredId пересчитается
  на первом же движении (emit leave/enter).
- Ноль накладных расходов без drag: один `if self.dragMove then` на входе.
- Это же место -- точка расширения для M18 modal input trap.

### 3. Z-order
- Новый proxy-метод `setZIndex(z)` (зеркалит setLayer: orderDirty + DIRTY_RENDER).
- `win:bringToFront()`: zIndex = max(соседи)+1, no-op если уже сверху.
  Для корневых окон "соседи" -- все корни (O(n) на клик, cold path).
- Любой mousedown по окну (бабблинг от частей) вызывает bringToFront.
- zIndex монотонно растёт при ping-pong окон -- нормализация отложена (M20).

### 4. Close (preventable)
- EVENT_CLOSE (6) + имя "close" в EventBus. emit добавляет
  `event.preventDefault()` (аналог stopPropagation) -- отмена действия по
  умолчанию. `win:close()`: emit("close") -> если не preventDefault ->
  destroy. Кнопка close -- NODE_TEXT "x" в bar (opt-in: closable=true).

### 5. События мыши с координатами
- mousedown/mouseup/click теперь несут `x, y` в eventData (нужны для grab-offset).

## Дефолты (M7-совместимость -- тесты M7 не менялись)
- bare window (без title/titleBar) -- 1 узел, БЕЗ bar, не draggable.
- title -> bar+text, draggable=true (бесплатно: bar уже есть).
- resizable/closable -- opt-in (по умолчанию off, иначе M7-подсчёт узлов сломался бы).
- modal=true -> LAYER_MODAL (полный focus trap -- M18).
- minW=80, minH=60 (клэмп в WindowMethods:setSize).

## Последствия
- Плюс: ScrollPanel (M13) строится на том же composite-паттерне (_parts.content).
- Плюс: drag/resize работают поверх существующих Dispatcher/EventBus/Storage --
  ядро не тронуто (только аддитивные расширения).
- Плюс: M7-тесты зелёные без правок (дефолты консервативны).
- Минус: animateTo({w/h}) у окна НЕ синхронизирует bar (animPool пишет storage
  напрямую, мимо override) -- размер окна анимировать нельзя (до M19).
- Минус: mousedown по close-button в момент между down/up теоретически тянет
  окно (drag без порога); клик без движения -- не тянет (guard по e.target).
- Минус: bringToFront поднимает z монотонно (не нормализует) -- M20 hardening.
