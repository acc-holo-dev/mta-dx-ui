# ADR-017: M13 ScrollPanel — composite + wheel + virtualization

## Контекст
Мастер-промт §7.3: "ScrollPanel — вертикальная/горизонтальная/обе, колесо
мыши, drag-scrollbar, smooth scroll, clipping. При скролле НЕ пересчитывать
всё UI — использовать существующие viewport/content bounds, clip rect и
culling. Архитектура должна сразу закладывать виртуализацию (100 → 10 000
логических элементов), через setVirtualProvider(fn)-подобный API, где
реальные узлы существуют только для видимых элементов — это тот же
freelist/pooling принцип".

M12 дал composite-proxy паттерн (один handle → несколько узлов). M13 —
первый реальный потребител: ScrollPanel = Visual + Container + Scrollable.

## Решение

### 1. Composite-структура (тот же паттерн, что Window M12)
- **Viewport** — PANEL с FLAG_CLIP (M5/M8), зацикливает детей.
- **Content** — 0x0 PANEL, enabled=false. M13-Builder skip'ает zero-size
  RECT (новое правило: zero-size panel без cmd). Дети прикрепляются СЮДА.
- **Track + Thumb** — по одной паре на ось (v/h/both). Track child viewport,
  thumb child track (zIndex 10/11 для hit-test над content).
- Proxy хранит `_parts = {content, trackV, thumbV, trackH, thumbH}` +
  `_sp` (состояние: axis, smooth, contentW/H, scrollX/Y, rows, rangeFirst/Last).

### 2. Scroll mechanics
- **setScroll(x, y)** — clamped (0..maxX, 0..maxY) + setPosition content
  (-x, -y) + emit EVENT_SCROLL + переразложить полосы.
- **getScroll() / getScrollMax() / scrollToPercent(px, py) / scrollBy(dx, dy)**.
- **Auto-measure** — если contentW/H не заданы, сканировать прямые дети
  content (O(children) per scroll action, cold path). Явный size для
  больших списков (виртуализация или ручной management).
- **Smooth scroll** — props.smooth=true → animateTo content {x=-x, y=-y},
  120ms EASE_OUT. По умолчанию false (инстант, DGS-like).

### 3. Wheel input (MTA: bindKey, не отдельное событие)
- Bootstrap: bindKey("mouse_wheel_up"/"mouse_wheel_down", "down", fn) →
  getCursorPosition() → kernel:onMouseWheel(cx, cy, dz).
- Dispatcher.onMouseWheel(px, py, dz) — hit test → emit EVENT_WHEEL на
  hit node (бабблится до ScrollPanel через обычный subscribe).
- ScrollPanel подписывается на "wheel" на viewport → scrollBy(0, -dz*step).
  DGS-конвенция: wheel → вертикаль (axis "v"/"both"); axis "h" → горизонталь.
- Wheel во время drag игнорируется (dispatcher guard).

### 4. Scrollbar (drag thumb)
- Track + thumb дети viewport. Track z=10, thumb z=11 (hit-test над content).
- **wireThumbDrag** — mousedown → grab offset → beginDrag(move) → setScroll
  по frac (localPos / (trackLen - thumbLen) * maxScroll).
- Auto-hide: maxScroll <= 0 → track/thumb setVisible(false).
- Track-click jump — отложен (не нужен для MVP).

### 5. Hit-test уважение clip-региона (M13 core-улучшение)
- **HitTest.pick** теперь проверяет: узел под clip-контейнером хитается
  ТОЛЬКО внутри clip-региона (clipX/Y/W/H из storage). Без этого клик
  "за краем" панели попадал в визуально обрезанный элемент.
- Регион 0/0/0/0 (первый кадр, layout ещё не вычислен) → skip проверки.

### 6. Zero-size RECT skip (M13 Builder improvement)
- **Builder.update**: если node type → CMD_RECT и (w<=0 или h<=0), команда
  не эмитится (освобождается, если была). Это делает content-контейнеры
  (0x0 panels) полностью невидимыми без draw call. TEXT/IMAGE не трогаем.
- Benefit: ScrollPanel content, любые placeholder-панели, future
  invisible containers — бесплатно.

### 7. Virtualization (setVirtualProvider)
- Provider = {count(), itemHeight, [itemWidth], [bind(row, idx)], [create(scroll, slot)]}.
- Row pool: array of proxies (children of content). На setScroll —
  пересчёт видимого диапазона (first..last, 1-based indices for user).
- Если диапазон сместился: bind rows (index = first + i), hidden rows →
  setVisible(false). Новые rows создаются через provider.create (default:
  0x0 panel with itemWidth × itemHeight).
- **Freelist principle**: rows переиспользуются, не уничтожаются (тот же
  pool-подход, что Storage/ProxyPool). 10k logical items → ~20 real nodes.
- count() вызывается per scroll action (cold path); user должен держать
  count() дешёвым (O(1), не O(n)).

### 8. Event constants
- **EVENT_WHEEL = 7** — data: {dz = -1/+1, x, y}.
- **EVENT_SCROLL = 8** — data: {x, y}. Emit на setScroll.

## Дефолты
- axis = "v", scrollbar = true, smooth = false, wheelStep = 40px.
- content auto-measure (если не задан contentW/H).
- Bare scrollpanel (без children) — content 0x0, полосы скрываются.

## Последствия
- Плюс: ScrollPanel работает поверх существующего Dispatcher/EventBus/
  Storage/Builder/Culling — ядро не тронуто (только аддитивные улучшения:
  HitTest clip-aware, Builder zero-size skip).
- Плюс: Virtualization готова для 10k+ items без per-node overhead.
- Плюс: Wheel + drag + programmatic — три пути скролла, все через один
  setScroll (единая точка clamp + emit).
- Минус: Auto-measure O(children) per scroll — для 10k+ реальных детей
  нужно явный contentSize или виртуализация.
- Минус: Smooth scroll via animateTo — cold path (per wheel notch); rapid
  wheel spam → interrupt-from-current (AnimationPool уже умеет).
- Минус: Horizontal virtualization (itemWidth) — задел есть, но M13
  фокус на vertical; горизонтальные виртуальные списки — M14+.
- Минус: Track-click jump не реализован (можно добавить в M14).
