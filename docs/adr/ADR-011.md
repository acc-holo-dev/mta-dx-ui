# ADR-011: RT Manager: единый владелец offscreen RT, пул по размерам, clip-стек

## Контекст
M8: реальная clip-обрезка через offscreen RT. Нельзя создавать RT per node (память + GC). Нужен пул RT по размерам + стек clip-регионов.

## Решение
RTManager (client/render/rt_manager.lua): pool [key=w×h] = { rt1, rt2, ... } (freelist по размерам), stack = { {x,y,w,h,rt}, ... }. pushClip(x,y,w,h): acquire RT (pool hit или dxCreateRenderTarget), dxSetRenderTarget(rt, true) (true = очистить), push на стек. popClip(): dxDrawImage(top.rt) в parent/screen с учётом offset, release RT, pop. offset = top.x/top.y (driver вычитает из coords). resize(): уничтожить все RT (onClientResolutionChange). RT Manager — global (DXUI.instance.rtManager), не per-node.

## Последствия
- Плюс: RT переиспользуются (pool по размерам), не аллоцируются каждый кадр.
- Плюс: clip-стек = O(depth), не O(n).
- Минус: nested clips M8 = single-level (innermost region); M10 = полный вложенный стек (StateCache отслеживает фактическую глубину, push/pop по цепочке clipX1..clipX4).
- Минус: RT — дорогая GPU-память; лимит пула — M9.
- Минус: resize уничтожает ВСЕ RT (старые привязаны к старому разрешению).
