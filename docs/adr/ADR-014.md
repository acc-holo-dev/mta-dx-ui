# ADR-014: M10 Debug-система — инспекция дерева, bounds-overlay, dirty-визуализация

## Контекст
M10 = production-ready. Разработчику нужен способ видеть структуру UI (дерево узлов), границы узлов и dirty-состояние — без замедления прода. §50 ТЗ: "production: minimal overhead".

## Решение
1. **Debug (client/debug/debug.lua)** — OFF by default (enabled=false), стоимость в проде = 0. Включение: DXUI.toggleDebug().
2. **dumpTree(maxDepth)** — итеративный DFS от корней (firstChild/nextSibling), печать тип/pos/size/world/flags/dirty. Без рекурсии (переиспользуемый стек).
3. **inspect(id)** — детальная информация об узле (slot/parent/local/world/flags/dirty/layoutMode/anchor/margin/padding/clip).
4. **drawBounds(driver)** — цветные рамки узлов (по типу, 0xAARRGGBB) + красная рамка для dirty-узлов. Вызывается из отдельного onClientRender handler ПОСЛЕ renderFrame (bounds поверх UI).
5. **hitTest(px, py)** — какой узел под курсором (через HitTest.pick).

## Последствия
- Плюс: zero overhead в проде (enabled=false).
- Плюс: все операции — cold path (вызываются вручную или из overlay).
- Плюс: без per-node обработчиков (единый проход по SoA-массивам, ADR-002).
- Минус: drawBounds рисует напрямую через driver.drawRect (не через StateCache) — намеренно, чтобы не влиять на state-дедупликацию основного конвейера.
- Минус: dumpTree/inspect — строковые аллокации (cold path, приемлемо).
