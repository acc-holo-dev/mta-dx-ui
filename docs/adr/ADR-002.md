# ADR-002: SoA (Structure of Arrays) вместо AoS

## Контекст
Хранение узлов: таблица полей на узел (AoS) vs плоские массивы полей (SoA). MTA Lua 5.1, тысячи узлов.

## Решение
SoA: storage.x[slot], storage.y[slot], storage.w[slot], ... — плоские Lua-таблицы, индекс = slot. id ↔ slot через idToSlot/slotToId._destroy: swap-with-last компакция (ARRAY_FIELDS — список всех SoA-колонк, переносится по ним).

## Последствия
- Плюс: cache-friendly обход по полю (hot-проходы читают одну колонку).
- Плюс: компакция O(1) на узел (swap-with-last по списку полей).
- Минус: новое поле = добавить в Storage.new + createNode + ARRAY_FIELDS (3 места).
- Минус: доступ к узлу = 2 lookup (idToSlot + column) — hot-функции кэшируют slot локально.
