# ADR-020: M16 Modal — overlay + focus lock + input trap

## Контекст
Мастер-промт §7.3: "Modal: overlay + focus lock + input trap". M12 дал
базовый modal-флаг (только setLayer(LAYER_MODAL)), но без overlay, без
блокировки фокуса и ввода. M16 закрывает полный modal-цикл.

## Решение

### 1. Наследование layer (Storage:setParent)
- **Проблема**: batcher сортирует по layer → zIndex → type → id, а layer
  НЕ наследовался детьми (всегда LAYER_BASE). У modal-окна (LAYER_MODAL)
  дети оставались LAYER_BASE и рендерились ПОД overlay.
- **Фикс**: Storage:setParent теперь копирует layer родителя в ребёнка.
  Новые дети modal-окна автоматически получают LAYER_MODAL.
- **setSubtreeLayer** (ui.lua): рекурсивно выставляет layer всему поддереву —
  для детей, созданных ДО setModal(true) (они не прошли через setParent
  после смены слоя окна).

### 2. Overlay (затемнение фона)
- Корневой PANEL (не ребёнок окна — должен покрывать весь экран, а не
  клипаться окном). LAY_REL(0,0) + размер screenW×screenH (LAY_REL влияет
  только на позицию, размер всегда в пикселях — см. layout.lua).
- LAYER_MODAL, zIndex = (depth-1)*2 — ниже окна, выше предыдущих modal.
- Цвет по умолчанию 0x80000000 (полупрозрачный чёрный), настраивается
  через opts.overlayColor; отключается opts.overlay = false.
- Resize при смене разрешения: Kernel:setScreenSize → Dispatcher:
  resizeModalOverlays(w, h).

### 3. Focus lock (Dispatcher)
- **modalStack** — стек активных modal-окон { windowId, overlayId }.
- **setFocus(id)**: при активном modal фокус только внутри окна
  (isDescendant(id, windowId)). Клик вне окна (пусто/overlay) НЕ трогает
  фокус — поле ввода внутри modal не теряет фокус.
- **isDescendant** — обход parent-цепочки (O(глубина)).

### 4. Input trap (Dispatcher)
- **onMouseDown/onMouseUp/onMouseWheel/onCursorMove**: при активном modal
  события вне окна (не isInsideModal) блокируются — фон под overlay не
  получает кликов/колеса/наведения.
- **isInsideModal(id)**: true для окна, его потомков и overlay (overlay
  нужен для dismissOnClickOutside).
- Клавиатура уже заперта: onKeyDown идёт на focusedId, который locked
  внутри modal.

### 5. API
- **setModal(v)**: v = true/false, либо таблица
  { overlay=bool, dismissOnClickOutside=bool, overlayColor=0xAARRGGBB }.
- **props.modal** в ui:window — true или та же таблица.
- **dismissOnClickOutside**: клик по overlay → window:close() (по умолчанию
  false — modal требует явного закрытия).
- **destroy()/close()**: автоматически снимают overlay + dispatcher.

## Дефолты
- overlay = true, dismissOnClickOutside = false, overlayColor = 0x80000000.
- z-порядок: overlay z=(depth-1)*2, окно z=(depth-1)*2+1 (вложенные modal
  выше предыдущих).

## Последствия
- Плюс: полный modal-цикл (overlay + focus lock + input trap) без изменения
  hot path — проверки только на input-события (cold path).
- Плюс: наследование layer — корректная семантика (дети в слое родителя),
  автоматически покрывает "новые дети modal-окна".
- Плюс: вложенные modal через стек (z-порядок по глубине).
- Минус: setSubtreeLayer рекурсивен (O(поддерева)) — cold path (open/close),
  modal-поддеревья неглубокие.
- Минус: нет авто-фокуса первого поля ввода при открытии modal (M17+).
- Минус: overlay не анимируется (появление/исчезновение мгновенное; M17+ —
  fade через AnimationPool).
- Минус: dismissOnClickOutside срабатывает на click (mousedown+up на overlay),
  не на mousedown — стандартное поведение кнопок.
