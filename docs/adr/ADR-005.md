# ADR-005: Handle/ID система: id стабильны, slot двигаются

## Контекст
Публичный API возвращает proxy-обёртки (handles). Внутри — числовой id (стабилен) и slot (SoA-индекс, двигается при destroy/swap).

## Решение
id: freelist (freeIds/freeIdsCount), nextFreshId — переиспользование id после destroy. slot = position в SoA-массивах; destroy → swap-with-last (последний узел занимает слот уничтоженного). Proxy-таблицы пулятся (Proxy.pool) — handle можно вернуть в пул и выдать другому id. idToSlot/slotToId — два массива-индекса.

## Последствия
- Плюс: handle можно держать в user-коде безопасно (destroy → no-op).
- Плюс: SoA-индексы плотные (count = живых узлов), обход быстрый.
- Минус: два lookup id→slot→column — hot-код кэширует slot.
- Минус: prevSibling/nextSibling/parent хранят ID (стабильны), не slot — иначе swap ломал бы ссылки.
