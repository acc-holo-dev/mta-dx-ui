# ADR-012: M9 Optimization — slot dirtyList, итеративный layout, DIRTY_POS

## Контекст
M8 завершён (RT clip, opacity, blur). M9 = оптимизация hot path. Бенчмарк (bench/bench.lua) показал: move_50 = 0.08–0.40 ms/frame (разброс ×5 — Windows os.clock нестабилен), hierarchy_500 = 0.72–0.96 ms/frame. Hot-путь: proxy setPosition → markDirty → Layout/Clip/Builder/Batcher → StateCache.

## Решение
1. **DIRTY_POS (0x091)** — слитый бит LAYOUT|TRANSFORM|RENDER для setPosition/setSize/anim. Один markDirty вместо трёх (M8).
2. **Slot-based dirtyList** — dirtyList хранит SLOT (не id). eachDirty/eachDirtyLive возвращают (id, slot) — без idToSlot lookup на каждом dirty-узле. markSlotDirty(slot, bits) — hot-вариант без lookup. clearFrameDirty — по slot.
3. **Итеративный layout-каскад** — переиспользуемый stack (stkSlot/stkPX/...), DFS. Каскад пересчитывает ВСЁ поддерево dirty-узла (DIRTY и НЕ-DIRTY — DIRTY-узлы пересчитываются самим каскадом, НЕ отдельными каскадами — порядок dirtyList гарантирует родитель-раньше-ребёнка).
4. **Кэш margin/padding** — marginCache[packed] = {mL, mT}. 4 деления на 256-е → 2 + табличное хит. Размер кэша = число различных значений margin/padding в UI (5–20), не число узлов.
5. **FLAG_OPACITY/FLAG_BLUR** — включаются proxy (setOpacity/setBlur). M8: были мёртвыми (introspection-only).

## Последствия
- Плюс: hot path — без idToSlot lookup (slot-based).
- Плюс: layout — итеративный (без рекурсии, без visited-set).
- Плюс: margin/padding — кэшировано (2 деления вместо 4).
- Минус: Windows os.clock нестабилен (разброс ×30) — финальные замеры в MTA (getRealTime).
- Минус: dirtyList по slot — destroy внутри кадра может оставить "дыру" (узел с этим slot занят новым узлом) — обработчик обязан проверять живость (hasSlotDirty).
