# ADR-015: Политика версии Lua в тестах -- только Lua 5.1 (lupa.lua51)

## Контекст
Проект разрабатывается для MTA:SA (Lua 5.1). Тесты долгое время гонялись под дефолтным lupa (Lua 5.5) -- см. README: "Lua 5.5 runtime". Это привело к невидимым расхождениям:

- `//` (целочисленное деление) в `layout.lua:57` -- синтаксис Lua 5.3+, в MTA 5.1 -- **SyntaxError** (ресурс не загрузится).
- `string.format("%d", 7/2)` -- в 5.1 -> "3", в 5.3+ -> ошибка.
- `#` на дырявых таблицах -- разные границы (5.1->4, 5.5->2).
- `math.type`, `math.maxinteger`, побитовые операторы (`&`, `|`, `<<`, `>>`) -- недоступны в 5.1.

Инцидент: M10 "production" никогда не запускался в реальном MTA -- `layout.lua` не загружается.

## Решение
1. **Тесты pinned к Lua 5.1**: `run_lupa.py` использует `import lupa.lua51` (доступен в venv).
2. **Запрет 5.2+ синтаксиса** в коде: `//`, `<<`, `>>`, `&`, `|`, `~`, `goto`, `table.unpack`, `math.maxinteger`, `math.type`, `string.pack` -- запрещены в `client/`. Допустимы только в `bench/` (где запускается отдельно, не в MTA).
3. **Портативные битовые операции**: в `storage.lua` оставлены `bitor/bitand` через арифметику (Lua 5.1-совместимые). В MTA можно заменить на нативный `bit.bor/bit.band` (оптимизация).
4. **Единый лоадер**: `tests/loader.lua` -- единственный источник порядка загрузки (соответствует `meta.xml`). Все тест-файлы делают `dofile("loader.lua")`.
5. **Subprocess per test**: `run_lupa.py` запускает каждый тест в отдельном subprocess (из-за `os.exit(0)` в тестах, убивающем процесс).
6. **SelfTest**: `client/core/selftest.lua` -- QUICK/FULL, запускается и в MTA, и через lupa.

## Последствия
- Плюс: тесты теперь гарантируют совместимость с MTA Lua 5.1.
- Плюс: единый лоадер устраняет дрифт порядка загрузки между тестами и `meta.xml`.
- Плюс: `os.exit` в тестах больше не ломает батчинг (каждый тест -- отдельный процесс).
- Минус: чуть медленнее запуск тестов (8 subprocessов вместо 1 процесса) -- некритично (< 2 сек суммарно).
- Минус: разработчикам нужно помнить о версии -- напоминание в README и этом ADR.
