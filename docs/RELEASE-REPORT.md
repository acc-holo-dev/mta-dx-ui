# Аудит и подготовка к релизу — DXUI v2 (mta-dx-ui)

Дата: подготовка релиза 2.1.0. Статус: **готово к релизу** (после фиксов в этом документе).

---

## 1. Резюме

Кодовая база в хорошем состоянии: чистая архитектура (AoS-ноды, единый
mutation layer, именованные dirty-категории, плоские списки для render/hit-test),
все 15 тестовых файлов зелёные, весь код синтаксически валиден под Lua 5.1
(как в MTA). Однако проект **не был готов к релизу** по нескольким причинам:

1. **Критично**: в репозитории лежали незакоммиченные фиксы рантайм-моста
   MTA (init.lua, dispatcher.lua, context.lua, backend_mta.lua) — то есть
   закоммиченная версия 2.1.0 при реальном запуске в MTA была сломана:
   - `init.lua` вызывал серверную `getScreenSize()` (в клиенте такой функции
     нет, клиентская — `guiGetScreenSize()`);
   - обработчик `onClientKey` передавал булево `press` как `state`, из-за чего
     события клавиш/text в игре не работали вовсе (мод-фикс уже лежал в дереве);
   - колесо мыши (`mouse_wheel_up/down`) не обрабатывалось;
   - бэкенд применял шейдер неправильно — в аргумент `postGUI` функции
     `dxDrawImage` (10-й параметр), а не как материал (5-й). Проверено по
     официальной вики MTA: материал-шейдер передаётся пятым аргументом.
2. **Критично**: даже после этих фиксов комбинации Ctrl (Ctrl+A/C/V/X в Edit)
   не работали бы в игре — `mods` всегда передавался пустым (`""`), т.к.
   `onClientKey` не отдаёт модификаторы. Добавлено отслеживание модификаторов
   в мосту.
3. **Версия**: `meta.xml` сообщал `2.0.0`, хотя коммит — 2.1.0. Не согласовано.
4. **Документация**: в README и шапке translation.lua пример локали
   `{ "menu.open" = "..." }` — синтаксическая ошибка Lua (строковый литерал
   как record-key); корректно `{ ["menu.open"] = "..." }`. Список виджетов в
   README противоречил сам себе (23 vs 24, упомянут не-виджет `tooltip`,
   пропущен внутренний `toggle`). Quick-start советовал добавлять свой
   `onClientRender`, что приводило бы к двойной отрисовке (init.lua рендерит
   все контексты сам). Дерево файлов в ARCHITECTURE.md устарело (нет 7 виджетов,
   тестов m23–25, есть несуществующий `demo.lua`).
5. **Пробелы в тестах**: не покрывались новый путь ввода `onCharacter`
   (MTA `onClientCharacter` → текст в Edit) и ctrl-шорткаты Edit.
6. **Инфраструктура git**: не было `.gitattributes` (на Windows autocrlf
   порождал CRLF-шум), не было тега релиза.

## 2. Методика проверки

- Запуск полного набора тестов: `python tests/run.py` (15 файлов, 382+ asserts,
  lupa/Lua 5.1 — тот же диалект, что в MTA).
- Синтаксическая проверка всех 64 `.lua`-файлов через `loadstring` в Lua 5.1.
- Сверка `meta.xml` ↔ `tests/loader.lua` ↔ реальных файлов (48/48 клиентских
  модулей в манифесте; loader намеренно пропускает только init.lua/export.lua).
- Ручной ревью всех модулей client/ (core, api, input, layout, render, style,
  text, animation, resources, utils, 25 widgets).
- Сверка фактов API MTA с официальной вики: `onClientKey(button, press)`,
  колесо через `mouse_wheel_up/down` (без release), `onClientCharacter(char)`,
  `dxDrawImage(image=material...)` — перекрёстно подтверждено.
